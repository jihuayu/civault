# 部署、备份与恢复

## 单实例部署

运行一个 `civault-server` 容器。后台通知、清理、Web 和两类 API 共用同一进程、单个 SQLite 文件和一个端口。不要将数据卷放在不可靠的网络文件系统，也不要用多个服务副本共享文件。

Compose 默认数据库命名卷、loopback 端口映射和 JSON 日志轮转（10 MiB × 5）。镜像是多阶段构建，最终容器不包含 Node、npm 或 Go 编译器。提供静态 Go 服务与 CLI、系统 CA、时区数据和读取初始化码需要的 `cat`。

启动配置仅包括主密钥环境变量及基础设施 flags：

| 项目                 | 默认    | 说明                                           |
| -------------------- | ------- | ---------------------------------------------- |
| `CIVAULT_MASTER_KEY` | 无      | 必须为标准 Base64 编码的 32 随机字节；永久保留 |
| `-listen`            | `:8080` | HTTP 监听地址                                  |
| `-data-dir`          | `/data` | SQLite 与首次初始化码目录                      |
| `-backup`            | 无      | 创建一致的 SQLite 快照并退出；目标必须是新文件 |

所有业务配置来自数据库。页面保存后每个新请求读到新配置；通知任务最晚在下一分钟扫描时重新计算。日志级别更新不需要重启。容器需要能访问 GitHub OAuth/API、`token.actions.githubusercontent.com` 和所选邮件服务商（`api.resend.com` 或 `api.agentmail.to`） 的 HTTPS 端口，并保持宿主时钟准确。

反向代理应保留外部 Host/Origin，并禁止缓存响应。不要在代理访问日志中记录 OAuth 回调 query string、认证头或请求/响应正文。服务端自己的运行日志只记录匹配路由，不记录原始 URL/query。当前登录限流按连接源 IP 计算，不信任客户端提交的转发头；经单一代理访问时共享该 IP 的登录限额（每分钟 5 次）。

## 备份

不要在运行中只复制 `civault.db`；WAL 中可能还有已提交内容。使用内置 `VACUUM INTO`，生成包含一致快照的独立数据库：

```bash
docker compose exec -T civault mkdir -p /data/backups
docker compose exec -T civault civault-server -backup /data/backups/2026-09-19.db
docker compose cp civault:/data/backups/2026-09-19.db ./civault-2026-09-19.db
```

备份命令是短暂维护进程，不启动第二个 HTTP 服务或 Worker。目标文件必须不存在，失败时退出码为 1。该操作使用 SQLite 的事务一致性机制，可能短暂影响数据库写入。

将数据库备份和主密钥分别保存到受控位置。备份中没有 Key 明文，但包含 Owner 邮箱、密码哈希、会话、配置密文、规则、审计和通知状态，同样需要保护。对外部备份文件限制访问权限。备份不会保存主密钥，丢失主密钥后无法解密历史数据。

## 恢复

建议恢复到一个**新的命名卷或空目录**，保留原始数据卷作为回退。停止服务后，将快照放入新数据卷的 `/data/civault.db`，目录属主 UID/GID 为 10001，目录权限 700，文件权限 600。不要把旧卷的 `-wal`、`-shm` 与恢复的快照混用。

在 Compose 的 volume 配置中选用新卷，使用原主密钥启动同版本或兼容新版本的镜像。打开控制台确认：

1. 不重新出现首次初始化入口。
2. 设置、Key 元数据、标签和规则存在。
3. 合成测试 Key 可以通过原授权工作流读取，错误主密钥启动失败。
4. 审计和通知状态完整。

一致性备份中包含会话与管理令牌；如恢复旧快照，应在页面修改密码以撤销恢复出来的旧会话/令牌，再创建新的管理令牌。备份之后发生的撤销无法存在于旧快照中。

`scripts/docker-smoke.mjs` 自动验证镜像的初始化、重启持久化、错误主密钥拒绝以及从备份恢复到新卷：

```bash
docker build -t civault:ci .
node scripts/docker-smoke.mjs
```

脚本仅使用带随机后缀的临时容器和数据卷，结束时清理这些测试资源。

## 迁移与升级

迁移位于 `internal/vault/migrations/001_init.sql`，编译进二进制，事务执行并记录 `schema_migrations`。本版支持 schema 1；已有 schema 1 可重复启动，遇到更新的数据库版本会拒绝降级。升级前创建快照并保留对应主密钥；无法回退的后续 schema 变更应通过恢复备份回退，不能直接运行旧二进制覆盖数据库。

## 到期通知故障处理

通知事件按「版本 ID + 有效期修订 + 提醒档位」去重。每个任务拥有固定正文和稳定的服务商幂等键。网络错误、429、5xx 及并发幂等冲突会退避重试，并遵守 Retry-After；非重试错误标记失败。

| 状态              | 含义 / 操作                                                                       |
| ----------------- | --------------------------------------------------------------------------------- |
| `pending`         | 等待第一次发送                                                                    |
| `sending`         | 已记录发送意图，可能正在请求；重启沿用相同幂等键                                  |
| `retry`           | 可重试，通常在 2 分钟至 1 小时内下一次尝试                                        |
| `sent`            | 邮件服务商返回 message ID；代表提供商接受，不代表邮件必达                            |
| `cancelled`       | 改期、换版本、禁用、删除或更紧急档位使任务不再适用                                |
| `failed`          | 提供商明确失败；检查配置和提供商状态                                              |
| `needs_attention` | 23 小时自动重试边界，或配置变更时已有不确定发送；人工核对邮件服务商 message/幂等记录 |

Resend 与 [AgentMail](https://docs.agentmail.to/idempotency) 的发送幂等窗口均为 24 小时，本系统在首个发送尝试后的 23 小时停止自动重试。不自动重发结果未知的旧任务；本版不提供绕过幂等窗口的“强制重试”按钮。可先核对提供商结果，再根据实际凭证情况更新 Key 版本/有效期或手动处理通知。

配置变更会取消从未尝试发送的旧任务，并根据新设置重算；已经尝试、结果尚不确定的任务标为需要处理。已发送记录保留。已经发出的 HTTP 请求无法收回，禁用或改期只能阻止尚未开始的发送和后续重试。

## 验证范围

本地无需第三方凭证即可运行 Go 集成测试、Action 进程测试和真实 API 的 Playwright 流程。OAuth、JWKS 和邮件服务商故障场景使用测试内注入的 HTTP Transport，不存在通过环境变量关闭生产认证的后门。

真实 GitHub OAuth 和邮件服务商测试邮件需要操作者自己的应用/域名配置；真实 OIDC 三平台验收使用仓库的手动工作流。Docker 脚本需要正在运行的 Docker daemon。详细测试入口见 README；外部集成测试结果应以实际运行记录为准。
